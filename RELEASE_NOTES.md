## macOS support, verified on real hardware

OBS Auto Recorder now runs natively on macOS, not just in theory -- this release brings in the real, hardware-tested port: tray icon, Settings, the clip editor (with real VLC video preview), global hotkeys, autostart, OBS/ffmpeg/VLC auto-discovery, game detection, and per-app audio isolation all confirmed working end-to-end on a real Mac. Getting there surfaced and fixed around a dozen real crashes and silent failures that only showed up on actual hardware (a Tk/AppKit main-thread conflict, the clip editor's video embedding, tray-menu crashes, broken Accessibility-permission checks, and more) -- this is the point where macOS support moved from "should work" to "does work."

- Per-app game audio isolation on macOS via ScreenCaptureKit, matching the existing Windows feature -- plus a small companion audio driver for games with no normal app bundle (Wine, Java-based games), whose audio can't be isolated any other way on macOS.
- macOS-specific installer: a double-clickable app in a DMG, or a one-line Terminal install; requests the Accessibility and Screen Recording permissions it needs up front and keeps them across updates.
- Linux support continues from the prior release (tray icon, clip editor, hotkeys, autostart, OBS discovery); see Known Limitations below for what's not there yet.

### Known limitations
- **macOS permissions are a manual, one-time step.** macOS requires granting Microphone, Camera, Accessibility, and Screen Recording access in System Settings before OBS (and this app) can work at all -- this can't be automated away, it's a deliberate macOS security restriction (no app can grant another app's permissions). The installer prompts for this up front.
- **macOS ships as two separate native builds** (Apple Silicon and Intel), not one universal binary -- numpy doesn't publish a universal2 wheel, so building one fat binary isn't currently possible. Download the one matching your Mac; no functional difference between them.
- **The audio-sync offset default is still Windows-measured.** ScreenCaptureKit's capture pipeline is different enough from Windows' WASAPI loopback that the built-in -27ms default has no real basis on macOS. Still just a default -- run the app's own "Calibrate Audio Sync" to get an accurate number for your setup.
- **Linux has no per-app game audio isolation at all.** Confirmed directly against a real, running PipeWire session: the stock OBS build on Linux exposes no audio-capture input kind capable of it. This is a real gap in what Linux's own OBS build currently supports, not something this app can work around -- Linux recordings still get Desktop Audio, mic, and app-specific captures (Discord, Spotify, etc.) where OBS does support those.

### Also in this release
- Fixed a real concurrency bug: the custom-keybind thread and the main watcher loop share one OBS connection, and a new periodic health check could land a request on it at the same moment as an "Add Marker" keypress, crossing wires and silently dropping the marker. Verified live under deliberate stress (14/14 markers landed correctly afterward) and with new tests proving genuine thread serialization.
- Recordings could end up permanently unnamed if the game crashed or was force-quit -- OBS can hold its own file handle open well past the old 5-second rename-retry window in that case. Budget raised to 30 seconds.

Covered by the full automated test suite (1,031 tests). The concurrency fix and mono-track handling were additionally verified live end-to-end against real recordings (Balatro, Deadlock) -- including a deliberate stress test that reproduced and then confirmed the fix for the marker race above, and a real clip-editor trim verified track-by-track (ffprobe + signal-level checks) to confirm every audio track survives a trim with its content and channel count intact.
